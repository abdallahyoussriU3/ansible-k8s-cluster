# ADR 003: Container Network Interface

- Status: Proposed
- Date: 2026-10-03

## Context

The Kubernetes cluster must support pod-to-pod networking, service networking, and NetworkPolicy enforcement in a secure and extensible way.

## Decision

Evaluate Calico and Cilium and select the one that best fits the actual VM networking, security, and operational constraints.

## Alternatives considered

- Calico
- Cilium
- minimal default networking without policy enforcement

## Reason

The selected CNI must support Kubernetes NetworkPolicies and provide a clear path toward future observability, ingress integration, and security controls.

## Consequences

- the CNI choice is dependent on confirmed node-to-node networking and VM security constraints
- policy enforcement must be validated after cluster bootstrap
- future workload security depends on the selected design

## Open question

The final selection depends on the actual VM network model, cluster size, and required observability or policy complexity.
